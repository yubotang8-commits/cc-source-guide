Day 20 - 工具系统（上）：工具的定义与注册

工具是什么

大模型只会"说话"，不能直接操作你的电脑。工具就是给大模型的"手"——让它能读文件、写文件、执行命令。

没有工具的大模型： 用户: "帮我创建一个 hello.txt" 大模型: "你可以在终端运行 echo hello > hello.txt" ← 只能告诉你怎么做 有工具的大模型： 用户: "帮我创建一个 hello.txt" 大模型: 调用 Write 工具 → 文件真的被创建了 ← 直接帮你做

CC 有哪些工具

工具目录功能
Bashtools/BashTool/执行终端命令
Readtools/FileReadTool/读取文件
Edittools/FileEditTool/编辑文件（局部替换）
Writetools/FileWriteTool/创建/覆写文件
Globtools/GlobTool/按文件名模式查找
Greptools/GrepTool/搜索文件内容
Agenttools/AgentTool/派生子 Agent
MCPtools/MCPTool/调用 MCP 外部工具

工具的定义结构

每个工具都需要告诉大模型"我叫什么、能做什么、需要什么参数"：

一个工具的定义（简化版）： { name: "Read", // 工具名 description: "读取文件内容", // 功能描述 input_schema: { // 参数格式 type: "object", properties: { file_path: { type: "string" }, // 文件路径 offset: { type: "number" }, // 起始行 limit: { type: "number" } // 读取行数 }, required: ["file_path"] } }

工具注册流程

src/tools.ts 中的注册过程： 1. 导入所有工具模块 2. 每个工具模块导出： ├── name 工具名称 ├── description 功能描述 ├── inputSchema 参数格式 └── execute() 执行函数 3. 注册到一个统一列表 4. 列表随系统提示词一起发给大模型 大模型看到工具列表，就知道自己"能做什么"。

工具描述的重要性

大模型选择工具的依据就是 description： 如果 description 写得模糊： "Read: 读取东西" → 大模型可能用错 如果 description 写得清楚： "Read: 读取指定文件的内容，返回带行号的文本" → 大模型能准确判断该不该用 所以工具描述也是提示词工程的一部分！
工具 = 大模型的"手"。定义工具就是告诉大模型"你有一双手，长这样，能做这些事"。
