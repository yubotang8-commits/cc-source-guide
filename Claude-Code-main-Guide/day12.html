Day 12 - 记忆系统（上）：记忆的类型与存储方式

为什么需要记忆

大模型本身没有"跨对话记忆"——你关掉终端再打开，它不记得你是谁。CC 的记忆系统就是为了弥补这一点。

没有记忆： 第1次对话: "我是做后端的" → 大模型知道了 第2次对话: "帮我写代码" → 大模型忘了你是做后端的 有记忆： 第1次对话: "我是做后端的" → CC 存到记忆文件 第2次对话: "帮我写代码" → CC 从记忆文件读取 → 提示词里加上"这个用户是做后端的" → 大模型按后端风格回答

四种记忆类型

类型存什么例子
user用户特征、偏好"用户是数据科学家，关注日志"
feedback用户的纠正和反馈"用户不喜欢结尾加总结"
project项目相关信息"合并冻结从3月5日开始"
reference外部资源指针"bug 在 Linear 的 INGEST 项目中追踪"

记忆文件在哪里

记忆存储目录： ~/.claude/projects/<项目slug>/memory/ ├── MEMORY.md ← 索引文件（入口，最多200行） ├── user_role.md ← 单条记忆 ├── feedback_style.md ← 单条记忆 ├── project_release.md ← 单条记忆 └── reference_dashboard.md ← 单条记忆

单条记忆的格式

每条记忆是一个 Markdown 文件，有 frontmatter 头部：

文件名：feedback_style.md --- name: 反馈风格偏好 description: 用户对回复风格的要求 type: feedback recallCount: 0 --- 用户不喜欢回复末尾加总结段落。 **Why:** 用户说"我看得懂 diff，不需要总结" **How to apply:** 回复时省略尾部总结，直接给出结果

MEMORY.md 索引文件

MEMORY.md 不存记忆内容，只存"指针"：

MEMORY.md： - [用户角色](user_role.md) — 数据科学家，关注日志系统 - [风格反馈](feedback_style.md) — 不要尾部总结 - [项目发布](project_release.md) — 3月5日合并冻结
记忆 = 文件系统上的 Markdown 文件。简单、可读、可手动编辑。MEMORY.md 是目录，每个 .md 文件是一条记忆。
