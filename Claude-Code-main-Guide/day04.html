Day 04 - 启动流程（下）：初始化与配置加载

init() 函数做了什么

昨天我们看到 main.tsx 调用了 init()，这是正式的初始化流程：

init() 函数（entrypoints/init.ts） │ ├── 1. enableConfigs() ← 加载配置系统 ├── 2. applySafeConfigEnvironmentVariables() ← 先应用安全的配置 ├── 3. applyExtraCACertsFromConfig() ← 加载证书 ├── 4. setupGracefulShutdown() ← 注册退出处理 ├── 5. 初始化 OpenTelemetry 日志 ← 遥测（延迟的） ├── 6. configureGlobalMTLS() ← 网络安全设置 ├── 7. configureGlobalAgents() ← 网络代理设置 └── 8. preconnectAnthropicApi() ← 提前建立网络连接 │ ▼ 信任对话框（Trust Dialog） │ ├── 用户确认信任 → 继续初始化 └── 用户拒绝 → 退出 │ ▼ initializeTelemetryAfterTrust() ├── 应用完整的环境变量 └── 初始化遥测/指标 │ ▼ runMigrations() ← 数据库迁移 prefetchSystemContextIfSafe() ← 预获取 git 状态等 startDeferredPrefetches() ← 后台预取 │ ▼ launchRepl() ← 启动 REPL 界面！

为什么要"信任对话框"

CC 可以读写你的文件、执行命令——这些都是危险操作。所以首次启动时会问你"你信任这个项目吗？"

就像手机 App 第一次要访问你的相册，会弹窗问你"允许吗？"。
CC 的信任对话框也是同样的道理：在获得完整权限前，先确认用户知情同意。

"预连接"是什么意思

preconnectAnthropicApi() 在启动阶段就提前和大模型服务器建立了 TCP + TLS 连接。

你打电话订外卖，如果先拨号等接通再说话，每次都有等待时间。
预连接就像提前拨好电话放在耳边，等你开口时对方已经在听了。

配置加载的优先级

配置加载顺序（后面的覆盖前面的）： 1. 程序内置默认值 2. 全局配置文件 (~/.claude/settings.json) 3. 项目配置文件 (.claude/settings.json) 4. 环境变量 5. 命令行参数 → 越后面的优先级越高
Day 04 的核心：启动不只是"打开界面"，而是一系列有序的准备工作——加载配置、建立网络、确认权限、预取数据。
