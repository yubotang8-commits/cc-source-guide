Day 23 - MCP 管理（上）：协议与客户端

MCP 是什么

MCP = Model Context Protocol（模型上下文协议）。它是一种标准，让 CC 能连接外部工具服务。

没有 MCP： CC 只能用内置工具（Bash、Read、Write……） 有了 MCP： CC 可以连接数据库、调用 API、操作第三方服务…… 就像手机装 App： 出厂自带 = 内置工具 应用商店下载 = MCP 工具

MCP 的通信方式

传输类型怎么通信场景
stdio启动一个子进程，通过输入输出通信本地工具服务
sse通过 HTTP 长连接远程服务
http标准 HTTP 请求远程服务
wsWebSocket 双向通信实时服务
sdkSDK 内部直接调用嵌入在其他程序中时

MCP 客户端架构

McpClient（src/services/mcp/client.ts） │ ├── 连接管理 │ ├── connect() ← 建立连接 │ ├── disconnect() ← 断开连接 │ └── reconnect() ← 重新连接 │ ├── 工具发现 │ └── listTools() ← 问服务器"你有哪些工具？" │ ├── 工具调用 │ └── callTool(name, args) ← 调用服务器的工具 │ ├── 资源访问 │ ├── listResources() ← 列出可用资源 │ └── readResource(uri) ← 读取资源内容 │ └── 提示词获取 └── listPrompts() ← 获取服务器提供的提示词模板

MCP 工具如何注册到 CC

MCP 工具注册流程： 1. McpClient 连接到 MCP 服务器 2. 调用 listTools() 获取工具列表 3. 每个工具包装成 MCPTool └── 工具名加前缀避免冲突 └── buildMcpToolName(serverName, toolName) 4. 注册到 CC 的工具列表 5. 大模型就能看到并使用这些工具 例：服务器 "db" 提供工具 "query" → CC 中工具名为 "db__query"

用比喻理解 MCP

MCP 就像 USB 接口： USB 是标准协议 → MCP 是标准协议 各种设备通过 USB 连电脑 → 各种服务通过 MCP 连 CC 鼠标、键盘、打印机 → 数据库、API、搜索引擎 你不需要为每个设备写专门的驱动（工具）， 只要它符合 USB 标准（MCP 协议），就能直接用。
MCP 的核心价值：标准化。只要服务实现了 MCP 协议，CC 就能直接调用，不需要为每个服务单独写集成代码。
