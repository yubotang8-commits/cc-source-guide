Day 03 - 启动流程（上）：从命令行到入口文件

从一条命令说起

当你在终端输入 bun run dev，发生了什么？

终端输入: bun run dev │ ▼ package.json 中的 scripts.dev: "dev": "bun run ./src/dev-entry.ts" │ ▼ 执行 src/dev-entry.ts │ ├── 检查 --version / --help 参数 ├── 扫描是否有缺失的相对引用 │ ▼ 如果没问题 → 导入 './entrypoints/cli.tsx' │ ▼ cli.tsx → 导入 src/main.tsx

main.tsx 的第一步

main.tsx 是整个程序的"大门"，它最先做的几件事：

main.tsx 开头（约第1-20行） │ ├── profileCheckpoint('main_tsx_entry') ← 记录启动时间点 ├── startMdmRawRead() ← 提前启动后台子进程 └── startKeychainPrefetch() ← 提前读取密钥信息 │ ▼ 调用 init() 函数（来自 entrypoints/init.ts）
这三个操作（profileCheckpoint、startMdmRawRead、startKeychainPrefetch）叫"预取"——在用户还没操作之前，先做一些耗时准备，让后续操作更快。

用餐厅比喻理解启动

餐厅开门前的准备： ├── 厨师到岗 ← profileCheckpoint（打卡记录时间） ├── 提前把冰箱插上电 ← startMdmRawRead（后台准备） └── 提前备好零钱 ← startKeychainPrefetch（预读取密钥）

package.json 中的关键命令

命令作用
bun run dev开发模式启动（入口：dev-entry.ts）
bun run start同 dev 的别名
bun run version只输出版本号，用于快速验证能否启动
假设你想确认代码改完后还能不能跑起来，不用等整个程序启动完：
bun run version → 只走启动流程的"前几步"，输出版本号就退出。
这就像餐厅开门前，先试试灯能不能亮，不用把所有菜都做一遍。
