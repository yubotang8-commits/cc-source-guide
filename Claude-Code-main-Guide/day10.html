Day 10 - 系统提示词构建（上）：基础模板

什么是系统提示词

每次跟大模型对话，CC 都会先发一段"背景说明"，告诉大模型"你是谁、你能做什么、规则是什么"。这段话就是系统提示词（System Prompt）。

发给大模型的消息结构： ┌─────────────────────────────┐ │ 系统提示词 (System Prompt) │ ← "你是 Claude Code，一个编程助手……" │ │ 每次请求都有，大模型看不到对话中它 ├─────────────────────────────┤ │ 历史消息1 (User) │ ← 用户之前说的 ├─────────────────────────────┤ │ 历史消息2 (Assistant) │ ← 大模型之前回的 ├─────────────────────────────┤ │ 当前消息 (User) │ ← 用户刚说的 └─────────────────────────────┘

系统提示词的来源

fetchSystemPromptParts() 做的事： 1. getSystemPrompt() └── 来自 src/constants/prompts.ts └── 这是"出厂设置"的基础提示词 └── 内容：你是谁、工具使用规范、行为准则…… 2. getSystemContext() └── 来自 src/context.ts └── 动态信息：当前目录、git 状态、操作系统…… 3. getUserContext() └── 用户偏好、历史行为 4. buildMemoryPrompt() └── 记忆内容（Day 12-14 详细讲） 5. CLAUDE.md 内容 └── 项目级自定义规则 6. MCP 工具描述 └── 外部工具的说明

基础提示词长什么样（简化版）

你是 Claude Code，Anthropic 的官方 CLI 工具，一个智能编程助手。 你可以在用户的终端中执行命令、读写文件、搜索代码。 核心行为： - 直接帮用户完成任务，而不是只给建议 - 先读代码再改代码 - 使用工具前先确认（根据权限模式） - 不要添加用户没要求的功能 工具使用： - Bash：执行终端命令 - Read：读取文件 - Edit：编辑文件 - Write：创建新文件 - Grep：搜索文件内容 - Glob：按模式查找文件 ...

为什么要每次都发系统提示词

大模型是"无记忆"的——每次调用都不记得上次聊了什么。所以每次请求都要把"说明书"带上，它才知道自己该怎么做。

就像你每次打电话给客服，都要先说"我是谁、我要办什么业务"。 客服不会记住你上次打过电话，每次都是全新的。 系统提示词就是那个"自我介绍"。
基础提示词是静态的，写在代码里。但系统提示词整体是动态的——每次请求会拼入不同的上下文信息。明天讲动态部分。
