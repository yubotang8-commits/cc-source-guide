2. Agent Loop — queryLoop()

核心文件: query.ts

2.1 循环结构

async function* queryLoop(params, consumedCommandUuids) {
  let state: State = { messages, toolUseContext, autoCompactTracking, turnCount, ... }

  while (true) {
    // ① 发送消息给 LLM API（流式）
    // ② 收集 model 的 tool_use blocks
    // ③ 并行/串行执行工具
    // ④ 判断是否继续

    if (no_tool_use)      return { reason: 'completed' }     // 正常退出：模型给出最终文本
    if (user_aborted)     return { reason: 'aborted_tools' }  // 用户中断
    if (hook_stopped)     return { reason: 'hook_stopped' }   // Hook 阻止
    if (max_turns)        return { reason: 'max_turns' }      // 达到最大轮次
    if (context_overflow) return { reason: 'prompt_too_long' } // 上下文溢出
    if (api_error)        return { reason: 'model_error' }     // API 错误

    // ⑤ 有工具结果 → 拼入 messages → 继续循环
    state = { messages: [...messagesForQuery, ...assistantMessages, ...toolResults], ... }
  }
}

2.2 正常退出 vs 异常退出

退出原因reason 值触发条件
正常完成completedLLM 返回纯文本，无 tool_use
用户中断aborted_tools用户在工具执行期间按 Ctrl+C 或 ESC
Hook 阻止hook_stoppedPostToolUse hook 返回 preventContinuation
轮次上限max_turns超过配置的最大 turn 数
上下文溢出prompt_too_longcompaction 后仍超出 token 限制
模型错误model_errorAPI 返回不可恢复的错误

2.3 流式工具执行

CC 独有特性：LLM 仍在输出时就 开始执行工具。

StreamingToolExecutor: LLM 流式输出 → 收到完整 tool_use block → 立即入队执行 ↓ isConcurrencySafe? → Yes → 并行执行（最多10个） → No → 串行等待 ↓ LLM 流结束 → 收集剩余工具结果 → 下一轮

3. 上下文管理（会话管理与持久化）

3.1 Transcript 持久化格式

文件格式: JSONL（每行一个 JSON 对象），路径: ~/.claude/projects/{hash}/{sessionId}.jsonl

// 每条记录类型（Entry）
type Entry =
  | TranscriptMessage          // user/assistant/system 消息
  | SpeculationAcceptMessage   // 推测接受记录
  | FileHistorySnapshotMessage // 文件历史快照
  | AttributionSnapshotMessage // 归属数据
  | ModeEntry                  // coordinator/普通模式切换
  | ContextCollapseCommitEntry // 上下文折叠提交

3.2 三级 Compaction 策略

① Session Memory Compact（轻量） 使用自动提取的会话记忆文件，快速压缩 ↓ 失败时降级 ② Reactive Compact（增量，feature-gated） 增量压缩，仅处理新增内容 ↓ 失败时降级 ③ Traditional Compact（全量） 启动 forked subagent 对整个对话做摘要 压缩后恢复最近5个被编辑文件到上下文
// Session Memory Compact 配置
DEFAULT_SM_COMPACT_CONFIG = {
  minTokens: 10_000,        // 压缩后至少保留 10K tokens
  minTextBlockMessages: 5,  // 至少保留 5 条文本消息
  maxTokens: 40_000,        // 硬上限 40K tokens
}

4. 记忆机制

4.1 CLAUDE.md 分层体系

4 级优先级，从低到高：

层级路径说明
1 - 全局管理/etc/claude-code/CLAUDE.md所有用户的全局指令
2 - 用户~/.claude/CLAUDE.md个人跨项目指令
3 - 项目CLAUDE.md / .claude/CLAUDE.md / .claude/rules/*.md可提交到代码仓库
4 - 本地CLAUDE.local.md不提交的本地指令

加载规则：从当前目录向根目录遍历。越靠近当前目录优先级越高（后加载的更受重视）。

4.2 自动会话记忆（Session Memory）

后台 forked subagent 自动提取对话笔记，不中断主流程。

DEFAULT_SESSION_MEMORY_CONFIG = {
  minimumMessageTokensToInit: 10000,  // 10K tokens 后启动
  minimumTokensBetweenUpdate: 5000,   // 每 5K token 增长更新
  toolCallsBetweenUpdates: 3,         // 或每 3 次工具调用更新
}

5. 提示词管理

5.1 Section 架构

系统提示词由多个 Section 组成，支持缓存和独立更新：

systemPromptSection(name, compute)           // 缓存直到 /clear 或 /compact
DANGEROUS_uncachedSystemPromptSection(name)  // 每轮都重新计算（MCP 指令等）

5.2 优先级

0. Override system prompt（如设置则替换所有） 1. Coordinator system prompt 2. Agent system prompt（proactive 模式追加，否则替换默认） 3. Custom system prompt（--system-prompt 参数） 4. Default system prompt + appendSystemPrompt 始终追加到末尾

6.2 会话状态机

type SessionState = 'idle' | 'running' | 'requires_action'

状态转换:
  idle → running         用户发送消息
  running → requires_action  工具需要用户授权
  requires_action → running  用户授权（allow/always）
  running → idle            模型完成回复（无 tool_use）
  requires_action → idle    用户拒绝（deny）

7. 安全机制

7.1 权限管道

工具调用请求 ↓ ① PreToolUse Hooks（可 deny/allow/ask） ↓ ② canUseTool 门控 ├─ 2a. checkRuleBasedPermissions（settings.json 规则） ├─ 2b. 工具特定检查（Bash: bashSecurity, pathValidation） ├─ 2c. auto 模式 → AI Classifier 评估 ├─ 2d. safetyCheck（不可被 classifier 覆盖） └─ 2e. 仍为 ask → 用户交互提示 ↓ ③ 沙箱内执行 ├─ 网络限制（allowedDomains） ├─ 文件系统限制（denyWrite/denyRead） └─ 后清理：清除可能植入的 git bare-repo 文件 ↓ ④ PostToolUse Hooks（可添加上下文或阻止继续）

7.2 三值权限模型

type PermissionBehavior = 'allow' | 'deny' | 'ask'
type PermissionMode = 'acceptEdits' | 'bypassPermissions' | 'default'
                    | 'dontAsk' | 'plan' | 'auto'

规则格式：ToolName(content)，如 Bash(npm test) 允许运行 npm test。
