关键设计差异

差异点说明
CC 的 JSONL vs CX 的 ThreadStore trait CC 直接写文件，简单但不可扩展；CX 通过 trait 抽象，支持任意后端（文件/数据库/S3）
OX 的事件溯源 OX 唯一使用事件溯源模式——所有变更先发 EventV2，再由 Projector 更新 SQL。其他两个直接操作存储
CC 的三级 Compaction CC 有最复杂的压缩策略，包括后台 session memory 自动提取，这在其他两个中没有
CX 的上下文窗口滚动 CX 独有的 roll_over 机制：可以不压缩就开新窗口，相当于"翻页"
