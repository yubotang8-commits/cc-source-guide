CC 记忆系统详解

// 四层 CLAUDE.md
1. /etc/claude-code/CLAUDE.md          ← 全局管理（最低优先级）
2. ~/.claude/CLAUDE.md                 ← 用户个人
3. CLAUDE.md / .claude/rules/*.md      ← 项目（可提交）
4. CLAUDE.local.md                     ← 本地（不提交）

// 自动 Session Memory
DEFAULT_SESSION_MEMORY_CONFIG = {
  minimumMessageTokensToInit: 10000,   // 10K tokens 后启动
  minimumTokensBetweenUpdate: 5000,    // 每 5K 增量更新
  toolCallsBetweenUpdates: 3,          // 或每 3 次工具调用
}
// 子代理只被允许编辑记忆文件

CX 记忆系统详解

// Phase 1: 从 rollout 提取
StageOneOutput {
  raw_memory: String,        // 详细 markdown 记忆
  rollout_summary: String,   // 紧凑摘要
  rollout_slug: String,      // 文件名 slug
}

// Phase 2: 合并（最复杂）
→ 获取全局 Phase 2 锁（互斥）
→ 准备 git 仓库作为记忆工作区
→ 启动受限 agent:
    ephemeral = true               // 不持久化
    memories.generate = false      // 不递归
    permissions.approval = Never   // 无需审批
    features: 禁用 Collab, MemoryTool
    sandbox: 仅工作区写入，无网络
→ agent 处理 → 验证 → git commit baseline

// 输出文件
$CODEX_HOME/memories/MEMORY.md          ← 最终合并记忆
$CODEX_HOME/memories/memory_summary.md  ← 摘要
$CODEX_HOME/memories/raw_memories.md    ← Phase 1 原始输出
关键差异：CX 的记忆系统最复杂——它用一个受限 agent 来"整理记忆"，而不是简单的规则匹配。这种设计允许记忆以更智能的方式被合并、去重和重组。

三个系统的记忆"哲学"对比

哲学CCCXOX
核心理念 用户显式编写 + AI 自动提取 AI 自主从历史中学习和积累 配置驱动，无自主记忆
类比 笔记本 + 助手自动做笔记 实习生从每次任务中学习和总结 工具箱里的说明书
持久化方式 Markdown 文件（人类可读可编辑） SQLite + Git 仓库（AI 管理） JSON 配置 + SQLite（结构化）
