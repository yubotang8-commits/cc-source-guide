代码对比：系统提示词组装

// CC — Section 架构
const dynamicSections = [
  systemPromptSection('session_guidance', () => ...),
  systemPromptSection('memory', () => loadMemoryPrompt()),
  systemPromptSection('env_info_simple', () => ...),
  DANGEROUS_uncachedSystemPromptSection('mcp_instructions', () => ...),
  systemPromptSection('scratchpad', ...),
  systemPromptSection('token_budget', ...),
]

// CX — 编译嵌入
let prompt = Prompt {
    input: turn_input,
    base_instructions: sess.get_base_instructions().await,
    ..Default::default()
};
// base_instructions 包含编译时嵌入的核心提示词

// OX — Source 代数
const context = SystemContext.combine([
  SystemContext.make({
    key: "core/environment",
    load: Effect.succeed(environment),
    baseline: (env) => ["环境信息:", env].join("\n"),
    update: (prev, curr) => `环境变更: ...`,
  }),
  SystemContext.make({
    key: "core/date",
    load: DateTime.nowAsDate,
    baseline: (date) => `今天的日期: ${date}`,
  }),
])
// 组装: system = [agent.system, systemContext.baseline]

提示词覆盖优先级

CC 优先级CX 优先级OX 优先级
0. Override（替换所有）1. BaseInstructions（固定）1. Agent system text
1. Coordinator prompt2. Compact summary（压缩摘要）2. SystemContext.baseline
2. Agent prompt3. Tool instructions
3. Custom prompt (--system-prompt)
4. Default prompt
+ appendSystemPrompt
设计哲学差异：CC 最灵活（可任意覆盖），CX 最简单（编译时固定+运行时变量），OX 最结构化（代数组合+增量更新）。CC 的 Section 架构适合快速迭代，CX 的编译嵌入适合性能，OX 的 Source 接口适合插件化扩展。
