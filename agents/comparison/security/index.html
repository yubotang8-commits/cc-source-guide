权限管道对比

CC — 规则 + 分类器 + 沙箱

工具调用 ↓ ① PreToolUse Hooks (deny/allow/ask) ↓ ② canUseTool 门控 ├─ checkRuleBasedPermissions (settings.json) ├─ bashSecurity / pathValidation ├─ auto 模式 → AI Classifier ├─ safetyCheck (不可覆盖) └─ 用户交互提示 ↓ ③ 沙箱执行 (network/filesystem) ↓ ④ PostToolUse Hooks

CX — Guardian + 平台沙箱

Shell 命令 ↓ ① is_safe_command? → 白名单直接批准 ↓ 否则 ② PermissionRequest Hooks ↓ ③ Guardian AutoReview (AI) 断路器: 3次连续拒绝 → 中断 turn ↓ ④ 用户审批 ↓ ⑤ SandboxManager::transform() macOS: seatbelt Linux: landlock + bwrap Windows: restricted token ↓ ⑥ 执行 + 违规检测

OX — 三值权限 + 路径隔离

工具调用 ↓ ① PermissionV2.evaluate(action, resource, rulesets) → deny: throw BlockedError → allow: 继续 → ask: 创建 pending → 等用户回复 ↓ ② 路径检查 (LocationMutation) relative path 逃逸 → PathError absolute path 在 location 外 → external_directory 权限 ↓ ③ 执行 (无系统级沙箱)

代码对比：权限断言

// CC — 工具级权限检查 (bashPermissions.ts)
classifyBashCommand(cmd) → safe/unsafe/critical
→ canUseTool(tool, input, context)
→ 用户提示或 auto-approve

// CX — Guardian 评估 (review.rs)
struct GuardianAssessment {
    risk_level: Low/Medium/High/Critical,
    outcome: Allow/Deny,
    rationale: String,
}
// 失败闭合: timeout/parse_error → deny

// OX — 三值评估 (permission.ts)
function evaluate(action, resource, rulesets) {
  return rulesets.flat()
    .findLast(match) ?? { effect: "ask" }  // 默认 ask
}
function assert(input) {
  deny → BlockedError
  allow → 继续
  ask → Deferred.await(用户回复)
}
安全成熟度排序：CX > CC >> OX。
Codex 安全最全面——OS 级沙箱 + AI Guardian + Shell 白名单 + Hook 系统 + Windows 特殊检测。
Claude Code 也很强——YOLO Classifier + 沙箱 + Shell 注入检测 + Hook。
OpenCode 最轻量——仅路径隔离 + 三值权限，无沙箱、无 AI 审查、无 Shell 检测。
